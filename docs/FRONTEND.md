# FRONTEND.md — как устроен интерфейс

Интерфейс живёт в том же приложении, что и API: Next.js App Router, React 19,
TypeScript strict. Отдельного фронтового проекта нет — страница и эндпоинт,
который её кормит, лежат в одном репозитории и проверяются одной сборкой.

Дизайн-система — `docs/design/01..06`. Её правила обязательны; расхождение
интерфейса с ней считается ошибкой, а не вкусовщиной.

---

## Где что лежит

    src/ui/                     дизайн-система: всё, что рисуется
      primitives/               кнопки, поля, карточки, значки, аватар, подсказки
      data/                     таблица, показатели, состояния загрузки/пусто/ошибка, значки статусов
      overlays/                 модальные окна, боковые панели, всплывающие сообщения
      layout/                   каркас: сайдбар, шапка, подвал, заголовки страниц
      search/                   окно глобального поиска
      notifications/            колокольчик и лента событий
      hooks/                    загрузка данных, изменения, мелкие браузерные хуки
      lib/                      обращения к API, форматирование, адреса страниц
    src/app/(auth)/login/       вход
    src/app/(app)/              внутренние страницы — все внутри общего каркаса

Импорт — из `@/ui`:

```ts
import { Button, Card, DataTable, useResource } from '@/ui'
```

Типы данных — только из `@/shared/contracts`. Импортировать что-либо
из `@/generated/prisma` на фронте запрещено.

## Правила, которые нельзя нарушать

1. **Никаких новых цветов, радиусов и размеров шрифта в компонентах.** Всё —
   переменными из `src/app/globals.css`. Если значения не хватает, оно добавляется
   в токены, а не пишется числом в одном месте.
2. **Новый вид кнопки/карточки не создаётся.** Сначала проверяется, решает ли
   задачу существующий компонент или его вариант (раздел 35 документа об интерфейсе).
3. **`null` — это «Нет данных», а не ноль.** Для показателей есть `MetricValue`
   и `KpiCard`, они это делают сами.
4. **Демонстрационные данные помечаются.** `isMock` и `containsMockData` —
   значок `<MockBadge />`. Это требование ТЗ, а не оформление.
5. **Текст ошибки приходит с сервера.** Он уже на русском и объясняет причину
   отказа — выводится как есть, своим «что-то пошло не так» не подменяется.
6. **У каждого экрана четыре состояния:** загрузка (скелетон), ошибка, пусто, данные.
7. **Клавиатура и фокус.** Любое действие достижимо с клавиатуры, фокус виден.
   У элемента без текста — `aria-label`.
8. **Ничто не выходит за ширину экрана.** Декоративные слои (фон, свечение,
   частицы) — `position: fixed; inset: 0; overflow: hidden; pointer-events: none`.
   Эффекты, которые идут за курсором, на тач-устройствах (`hover: none`)
   стоят неподвижно в пределах экрана. У `html` и `body` стоит
   `overflow-x: clip`, его не убирать: без него iPhone Safari сдвигал
   страницу вбок из-за пятен фона правее экрана (PR #73).
9. **Текст читается на проекторе 1280×720 (решение 91).** Кегль не меньше 12 px
   (`--text-caption-size`), контраст не ниже 4,5:1. `--text-disabled` — только
   для разделителей и выключенного; подпись, которую нужно прочесть, — `--text-tertiary`.

## Загрузка данных

```tsx
const universities = useResource<UniversityListItemDto[]>(`/api/universities${buildQuery({ q, page })}`, {
  keepPreviousData: true,
})
usePageInRange(page, setPage, universities.meta)

if (universities.isLoading) return <TableSkeleton />
if (universities.error) return <ErrorState error={universities.error} onRetry={universities.reload} />
if (universities.data?.length === 0) return <EmptyState title="Записей нет" />
```

`useResource` сам отменяет устаревший запрос и различает первую загрузку
и обновление. Данные он отдаёт только того адреса, который запрошен сейчас:
адрес `null` — данных нет, новый адрес — загрузка, а не данные прежнего.
Прежние строки на время загрузки показывает только список, который попросил
об этом сам (`keepPreviousData`) — там адрес меняют фильтр, страница или
«показать ещё». Карточке по id, поиску и зависимым спискам это нельзя: прежние
данные там — другая запись (решение 54).

Переход «строка → карточка» подключён в общей таблице и шапке страницы
(`ui/lib/morph.ts`): отдельная страница ничего для него не делает. Своя ссылка
на объект вне таблицы может вызвать `startMorph(элемент, событие)` — посадка
произойдёт на заголовке карточки сама. Если в ссылке несколько текстов
(строка-маршрут, строка рейтинга), название помечается `data-morph-title`:
иначе полетит самый длинный текст. Так подключены ссылки главной.

Переход «карточка раскрывается в свою страницу» — в каркасе
(`ui/layout/navigation-motion.ts`), на View Transitions: браузер снимает старый
и новый экран и анимирует снимки на видеокарте. Срабатывает только на карточках
объектов — строках реестров и ссылках-плашках с помеченным названием
(`data-morph-title`). Меню, шапка, кнопки и ссылки разделов переходят сразу.
Хореография: соседние строки расступаются от нажатой, остальная страница уходит
вглубь; нажатая плашка вырастает в рабочую область, и внутри неё проявляется
карточка; название перелетает в её заголовок `h1`. Страницам ничего делать не нужно.
Что стоит знать:

- анимируются только положение, размер и прозрачность снимков. Тени с размытием
  и цвет фона у растущей плашки не анимировать: она размером со страницу,
  и перерисовка на каждом кадре даёт рывки;
- элемент, взятый в переход, не должен исчезать во время анимации — иначе браузер
  обрывает её. Поэтому заготовки загрузки помечены `data-skeleton`: переход ждёт
  данных до 0,26 с;
- меню, шапка и кнопка поиска помечены `data-nav-chrome` — они остаются над движением
  и сами переход не запускают;
- то, что страница делает по приходу данных (прокрутка к этапу по ссылке), во время
  перехода выполняется сразу, без плавности: проверка `NAV_TRANSITION_ATTRIBUTE`;
- новая страница ждётся до 0,5 с; не успела (в разработке первая сборка страницы
  идёт секунды) — старый экран отпускается, и она приходит обычным появлением;
- без поддержки View Transitions и при «уменьшить движение» работает прежний путь:
  появление блоков по очереди и перелёт названия (`ui/lib/morph.ts`).

`usePageInRange` возвращает на последнюю существующую страницу, если выдача
сократилась под человеком: иначе он оставался на пустой странице без
переключателя страниц.

Доли от 0 до 1 (покрытие, дефицит, вес показателя) выводит `formatShare` — целым
процентом; спрос — `formatDemand`, «77 из 100», по тому же `outOf100`, что и тексты
сервера. Своё `Math.round(x * 100)` на странице не пишется: так одна величина
расходилась по экранам.

`CellText` обрезает текст ячейки в одну строку; длинное название, которое и есть смысл строки (полное имя вуза), — `lines={2}`.

Пометку демо-данных в списке расставляет `mockMarks(rows)`: `section` — у раздела,
`row(row)` — у строки только при смешанной выдаче. Одинаковая плашка в каждой
строке ничего не различает и раздвигает таблицу.

Пояснения к фильтрам — в `Toolbar note`, строкой под панелью, а не `hint` у поля:
панель выравнивает поля по нижнему краю, и подсказка под одним полем поднимала
его выше соседних.

Данные, на которых построена рекомендация (`relatedData`), выводятся через
`describeRelatedData` (`ui/lib/related-data.ts`): подписи по-русски, даты
по Москве, статусы словами, идентификаторы скрыты, порядок строк задан там же —
jsonb в базе ключи переставляет. Новое поле правила без подписи не теряется,
а выводится как есть; подпись к нему добавляется в тот же файл.

Изменения — `useMutation`:

```tsx
const save = useMutation(async (input: PatchInput) => apiPatch<WorkflowStageDto>(`/api/workflow/stages/${id}`, input))
const result = await save.run(input)
if (!result.ok) toast.error(result.error.message)
```

Ошибку брать из результата `run()`, а не из `save.error`: внутри обработчика
`save` — объект того рендера, в котором обработчик создан, и сразу после `await`
его `error` ещё пустой. Так однажды пропал отказ контрольной точки — главное,
что должен увидеть человек на показе.

**Сессия.** На 401 оба хука сами уводят на вход (`src/ui/lib/session.ts`):
снимают старую сессию и открывают `/login?reauth=1&from=<где был>`. Параметр
`reauth` нужен middleware: он видит только наличие cookie и вошедшего
со страницы входа отправляет на главную. Когда cookie остался, а пользователя
за ним нет (демо-данные перезалиты, пользователи созданы заново), главная
уводила на вход, вход — на главную, и экран оставался пустым (решение 48).

Отказ системы (409 `INVALID_TRANSITION`) — это нормальный ответ, а не сбой:
его текст показывается пользователю целиком.

## Каркас и страницы

`src/app/(app)/layout.tsx` даёт каркас: боковое меню, шапку, подвал и поиск.
Страница описывает только содержимое:

```tsx
<PageHeader title="Университеты" description="Реестр вузов, с которыми ведётся работа" />
<Toolbar>…фильтры…</Toolbar>
<Card padding="none">
  <DataTable rows={…} columns={…} getRowKey={…} getRowHref={…} />
  <Pagination … />
</Card>
```

У `DataTable` два вида. По умолчанию (`appearance="grid"`) это плотный список
с линиями. `appearance="cards"` — каждая строка отдельной плашкой: крупнее,
с воздухом, с меткой при наведении. Карточке под таким видом нужен прозрачный
фон, иначе плашки с ним сливаются. Главное в строке помечается `data-morph-title`:
оно же подсвечивается при наведении.

**Реестры — лентой** (`appearance="list"`, решение 69): карточка с названием,
строкой пояснения (`ListTitle`) и 3–4 фактами справа; `hideInList` прячет столбец,
оставляя сортировку. Ниже — прежнее правило плотности, которое решение 69 отменяет
для реестров до согласования с Артуром.

**Реестры — плотные** (решение 44, подтверждено Артуром 24.09, решение 65):
вузы, программы, связки и документы — `grid`, 20–25 строк на экран, строка 32 px,
каждая ячейка — одна строка. Уточнение (сокращение вуза, регион, продукт, код
программы) стоит после главного и обрезается первым; главное не сжимается ради
него (`flex: none; max-width: 100%`) — иначе доля пикселя сжатия уже рисует
многоточие. Уточнение, которому в узком столбце места не хватит никогда, не
показывается обрывком, а уходит в подсказку ячейки. Проверка — высота строк
на 1440×900 и отсутствие прокрутки таблицы на 1280.

Под всеми страницами — живой фон (`src/ui/layout/LiveBackground.tsx`): мягкое
фиолетовое свечение плывёт за курсором, второе, глубже, тянется за ним с запаздыванием,
под ними медленно дышит дымка. Цвета — токены `--bg-glow*` и `--bg-haze-*`. Двигается
только положение слоёв; при «уменьшить движение» и на сенсорных экранах свечение
стоит на месте. Карточки лежат на фоне непрозрачными поверхностями — текст в них
читается как прежде.

Поиск открывается кнопкой с лупой в шапке на любой ширине и по Ctrl K; плавающей
кнопки нет (решение 129). Подвал — одной строкой со служебными ссылками: разделы в нём не повторяются.
Реестры вида `cards` на экране до 720 px раскладываются карточками: у ячеек есть
`data-label` с названием столбца, сортировка — кнопками над списком.

Состав бокового меню — `src/ui/layout/navigation.ts`. Пункт добавляется туда
и только тогда, когда роль действительно может им пользоваться.

## Режимы интерфейса

Режимов два (решение 80), выбирает сам человек — кнопками «Рабочий / Презентационный»
в шапке рядом с именем (экран от 1081 px), в «Настройках» и в личном кабинете.

- **Рабочий** — по умолчанию для всех ролей. Реестры вузов и программ по умолчанию
  списком; на главной нет бегущей строки, колец и карты — «Требует внимания»
  и «Приоритетные действия» идут сразу за полосой «Активно сейчас»; нет заставки,
  «рассыпки» букв, импульсов по проводам графа, «магнитных»
  кнопок, перекатывания букв в меню; фон неподвижен.
- **Презентационный** — весь визуал дизайнера (решения 70, 73, 79).

Выбор хранится в `localStorage` (`skilllink.uiMode`) и стоит атрибутом
`data-mode="work|showcase"` на `<html>` — его ставит встроенный скрипт до первой
отрисовки (`UI_MODE_BOOT_SCRIPT` в `ui/lib/ui-mode.ts`), поэтому ничего не мигает.

```tsx
const { isWork } = useUiMode()          // спрятать блок в рабочем режиме
const calm = useCalmMotion()            // «уменьшить движение» ИЛИ рабочий режим
```

Правила для нового визуала:

- декоративное движение (рост, прорисовка, пружины, счётчики, пульсация) проверяет
  `useCalmMotion()`, а не `usePrefersReducedMotion()`: иначе оно будет двигаться
  и в рабочем режиме;
- в CSS — `:global(html[data-mode='work']) .класс { … }` рядом с правилом
  `prefers-reduced-motion`;
- украшение, которое занимает место (лента, карта, кольца), в рабочем режиме
  не рисуется и не запрашивает свои данные (`isWork ? null : адрес`);
- переходы между экранами (раскрытие карточки, перелёт названия, появление блоков)
  — связь экранов, а не украшение: они смотрят только на «уменьшить движение»;
- визуал дизайнера не удаляется — только прячется в рабочем режиме.

## Окна: боковая панель или модальное окно (решение 155)

Один выбор на весь интерфейс (ТЗ дизайна 26–29.09, п. 1.3):

- **Боковая панель (`Drawer`)** — посмотреть объект, не уходя со списка: карточка
  продукта, вендора, документа, рекомендации, история этапа. Список остаётся за панелью,
  объект живёт в адресе (`?product=`, `?vendor=`, `?recommendation=`), «назад» закрывает панель.
- **Модальное окно (`Modal`)** — действие, которое нужно довести до конца или отменить:
  формы создания и правки, смена ответственного, срок этапа, подтверждение архива и удаления.
- Вуз, программа и связка — **страницы**: у них вкладки и много действий, в панель они не помещаются.

Новый экран выбирает формат по этому правилу, а не по вкусу.

## Выгрузки файлов

Любая кнопка скачивания — `DownloadButton` (`src/ui/data/DownloadButton.tsx`), не ссылка:
файл забирается запросом (`apiDownload`), у кнопки есть «готовим» (крутилка), «готово»
(сообщение с именем файла) и ошибка сервера по-русски. Используется в реестрах вузов,
программ, связок, в отчётах по ТЗ и в «Моих данных».

## Настройки

`/settings` — колонка разделов слева, справа один раздел строками «название — значение
или действие» (решение 91). Раздел хранится в адресе (`#integrations`). Строки —
`settings/SettingsRow.tsx` (`Row`, `Hint`, `RowsSkeleton`): их берут и вкладки
в отдельных файлах — страница Next не может экспортировать ничего, кроме себя.

| Вкладка | Кому | Что там |
| --- | --- | --- |
| Интерфейс | всем | режим «Рабочий / Презентационный» |
| Рыночные данные, Источники данных | с правом аналитики | активный источник, синхронизация, источники |
| Интеграции | с правом аналитики | рыночные данные, LMS, сайт и **ИИ-помощник** (с 25.09.2026): «Выключен — ответы пишет шаблон» или «YandexGPT (yandexgpt-lite) — подключён»; ключей в ответе API нет |
| **Пользователи** | только `ADMIN` | `settings/UsersSection.tsx`: список с поиском по ФИО и почте, фильтрами роли и доступа; «Завести пользователя», окно пользователя с ФИО, должностью, ролью, вузом представителя и разделом «Доступ» — выдать временный пароль, заблокировать/разблокировать (`settings/UserModals.tsx`) |
| **Журнал действий** | только `ADMIN` | `settings/AuditSection.tsx`: записи `GET /api/audit` строками — действие словами (`AUDIT_ACTION_LABELS`), время, кто, объект, кратко подробности (`settings/audit-view.ts`), «Открыть», если объект открывается в интерфейсе; фильтры по сотруднику, действию, объекту и периоду (московские сутки) |
| О системе | всем | состояние системы, спецификация OpenAPI |

Вкладки администратора другим ролям **не рисуются вовсе** — ни пункта в колонке,
ни раздела по адресу `#users`: он открывает «Интерфейс». Проверки прав — на сервере;
интерфейс лишь заранее показывает то, от чего сервер откажет: свою роль и свою
блокировку администратор не меняет (поля выключены), смену роли менеджера
с открытыми связками окно запрещает с объяснением «сначала передайте связки».

**Временный пароль** показывается один раз — окном, которое не закрывается щелчком
мимо, с «Скопировать» (при недоступном буфере обмена пароль выделяется) и просьбой
передать его лично. **Смена своего пароля** — в личном кабинете, строка «Пароль»
в блоке «Настройки» (`profile/ChangePasswordModal.tsx`): текущий, новый, повтор;
повтор сверяет форма. Если пароль выдан администратором (`passwordTemporary`
в `GET /api/me`), над кабинетом — плашка «смените временный пароль».

## Роли

Текущий пользователь — `useCurrentUser()`. Права приходят с сервера
(`permissions.canWrite`, `canSeeAnalytics`, `canUsePortal`, `canWritePortal`,
`canSeeContactDetails`, `isAdmin`):
матрица доступа не дублируется на фронте.

## Отчёт руководителю и печать

`/reports/portfolio` (решение 97) — состояние сотрудничества с вузами на листе A4:
шапка с датой, автором и пометкой демо-данных, ключевые показатели, все проблемные
этапы, пять приоритетных действий, пять лучших программ, покрытие навыков, внизу —
откуда данные. Ссылка — кнопкой «Отчёт руководителю» в шапке главной и аналитики.

- **PDF делает браузер:** кнопка «Печать / PDF» — `window.print()`, в окне печати
  «Сохранить как PDF». Имя файла — заголовок вкладки, его ставит страница.
- **Лист — это `[data-print-document]`.** Пока он на странице, `@media print`
  в `globals.css` печатает только его: каркас, заголовок страницы и кнопки скрыты.
  Другие страницы листа не имеют и печатаются как прежде. Новому печатному документу
  достаточно этого атрибута на своём корне.
- **Поля и размер — именованной страницей** (`@page report` в CSS-модуле и `page: report`
  на листе): безымянный `@page` остался бы в силе и после ухода со страницы.
- **Экранные правила узкого экрана — `@media screen and (max-width: …)`:** печатная
  область A4 — 688 px, и правило без `screen` сработало бы и на бумаге.
- **Цвета листа — токены бумаги** (`--paper*`, `--ink*`), одинаковые на экране и в печати.
  Значки дизайн-системы внутри листа переключаются на них переопределением переменных
  (`--text-warm`, `--status-danger` и др.) на корне листа.
- Строки таблиц и пункты списков помечены `break-inside: avoid`, заголовки блоков —
  `break-after: avoid`. Результат проверяется `page.pdf({ format: 'A4' })` в Chromium без окна.

## ИИ-помощник

Черновики помощника (решение 90) — `src/app/(app)/AiDraft.tsx`: `AiAssistCard` — блок
с кнопкой («Что сделать сегодня» на рекомендациях, «Сводка» во вкладке «Рекомендации»
карточки связки), `AiDraftView` — сам черновик (письмо вузу показывается им в модальном
окне по кнопке «Черновик письма» в строке рекомендации, только при `canWrite`).

Правила:

- **ничего не генерируется при открытии страницы** — только по кнопке: каждый вызов
  модели стоит денег и идёт в лимит пользователя;
- **источник виден всегда** — `aiDraftSourceNote(draft)` из `shared/contracts`:
  «Черновик ИИ (YandexGPT) — проверьте перед отправкой» или «Шаблон без ИИ: помощник
  не подключён». Шаблон не выдаётся за ИИ и наоборот;
- под черновиком — факты, из которых он собран (`draft.facts`): ровно то, что ушло
  в модель.

## Выпадающие списки

`Select` из `@/ui` — свой, не системный `<select>`. Системный отдаёт список
браузеру: он рисуется средствами операционной системы и не знает ни про тёмную
тему, ни про скругления (раздел 22 документа об интерфейсе). Свой работает
с клавиатуры: стрелки перебирают, Enter выбирает, Escape закрывает.

```tsx
<Select label="Статус" placeholder="Любой статус" value={status} onValueChange={setStatus}
        options={STATUSES.map((value) => ({ value, label: LABELS[value] }))} />
```

**Вузы, программы, связки — только `RemoteSelect`.** Их бывает тысячи, и загрузить
список целиком нельзя. Раньше здесь стоял `pageSize=100`, и всё, что дальше сотни,
молча пропадало: на базе с тысячей вузов связку с вузом на «Т» было не создать.
`RemoteSelect` берёт первые пятьдесят вариантов, остальное находит поиском
на сервере и пишет «показаны 50 из 1 004». Поле поиска появляется, только когда
вариантов больше двенадцати: в демо-наборе из шести вузов список выглядит
как обычный.

```tsx
<RemoteSelect<UniversityListItemDto>
  label="Вуз" endpoint="/api/universities" params={{ withRating: 'false', sort: 'name' }}
  toOption={universityShortOption} placeholder="Все вузы"
  value={universityId} onValueChange={setUniversityId} />
```

Подписи вариантов — общие (`universityShortOption` в фильтрах, `universityFullOption`
в формах, `programWithUniversityOption`, `cooperationOption`), чтобы один вуз
не назывался на разных экранах по-разному. Программа без выбранного вуза
подписывается вместе с вузом: одноимённые программы разных вузов иначе неотличимы.

**Escape закрывает только верхний слой.** Выпадающий список, модальное окно,
поиск, колокольчик — стопка (`src/ui/hooks/escape-stack.ts`). Раньше каждый слой
слушал клавишу сам, и Escape в списке «Вуз» закрывал форму «Создать связку»
со всем введённым. Новому всплывающему слою достаточно `useEscape(close, isOpen)`.

**Фокус — внутри открытого окна.** `Modal` и `Drawer` держат фокус у себя
(`src/ui/hooks/focus-trap.ts`): при открытии он встаёт на первое поле формы
(в боковой панели — на саму панель), Tab и Shift+Tab ходят по кругу, после
закрытия фокус возвращается на кнопку, которая окно открыла. Раньше окна
объявляли себя модальными, но Tab уводил на меню под окном.
