**Прогноз «дойдёт ли связка до вехи» (26.09.2026, решение 135, ветка `feat/forecast`).**
Логистическая регрессия (L2, метод Ньютона) на чистом TypeScript поверх признаков связки
на момент времени, без утечки будущего; временное разбиение обучение/проверка, AUC, Brier,

Объяснение прогноза связки — топ-3 «за» и «против» обычными фразами, вклад признака
складывается ровно в вероятность (тестами). Формулы и как объяснить жюри за минуту —
[FORECAST_MODEL.md](FORECAST_MODEL.md). `GET /api/analytics/forecast/model`,
`GET /api/cooperations/:id/forecast`, `POST /api/analytics/forecast/train` (администратор,
`npm run forecast:train`), `npm run forecast:report` — печать метрик для слайда. Таблица
`forecast_models` — не персональные данные (`DSAR_NOT_PERSONAL`). Права — как у остальной
аналитики, представителю вуза недоступно.

### Ограничение перебора пароля

- Пять неудачных попыток подряд закрывают учётную запись на 15 минут, удачный вход
  счётчик обнуляет. Значения в `src/shared/config/auth.config.ts`, помечены TEMP.
- Проверка до запроса к базе и до bcrypt: заблокированная попытка ничего не стоит.
- Ответ не отличается от «неверный пароль» — иначе перебираются существующие адреса.
- Попытки во время блокировки её не продлевают: иначе перебор стал бы способом
  заблокировать чужой вход.
- Счётчик в памяти процесса — ограничение описано в `docs/SECURITY_LIMITATIONS.md`.

### Демонстрационный набор

- Пять показателей дашборда заполнены сразу после `npm run db:seed` — раньше два
  из них выглядели сломанными на свежей установке.
- **Журнал действий заполняется посевом.** Раньше посев писал историю этапов,
  но не журнал: администратор видел пустой раздел при трёх десятках завершённых
  этапов, а показатель «операций на связку» — «Нет данных».
- **Часть завершённых этапов закрыта с опозданием** (`lateStages`). Без них
  показатель «этапы, закрытые в срок» по построению равнялся 100 %, и контроль
  сроков на демонстрации нечем было показать. Сейчас 87,9 %.
- **Рекомендации генерируются посевом** настоящим движком правил, а не сочиняются.
  Без этого дашборд открывался с пустым блоком «приоритетные действия»: рекомендации
  появлялись только после явного нажатия, и раздел выглядел неработающим.
- Все пять правил рекомендаций срабатывают на демо-данных.
- Повторный посев не удваивает записи.

### Закрытая связка не требует внимания

- Закрытые связки исключены из просроченных, заблокированных и проблемных
  на дашборде. Раньше сотрудничество, доведённое до конца или отменённое,
  продолжало требовать действий вечно — при том, что его этапы заморожены
  и изменить их нельзя.
- Генератор рекомендаций всегда работал только по действующим связкам:
  система противоречила сама себе.
- В демонстрационном наборе появилась завершённая связка — и для показа итога,
  и чтобы правилу было на чём проверяться.
- Из тех же списков убран **этап 14**: он вычисляется автоматически, руками
  не меняется, и просрочен ровно потому, что не закрыты этапы 1–13 — они

### Рейтинг вуза (пункт 7.2 ТЗ)

- Агрегируется из рейтингов программ вуза: новых факторов не вводится.
- Нормирование по всей выборке программ, а не внутри вуза — иначе вуз с одной программой
  всегда получал бы 100 баллов.
- Программа без данных не входит в среднее и не тянет балл вниз (решение 8).
- Приходит в реестре по умолчанию (решение Артура, пункт 11); `withRating=false`
  отключает расчёт. Фильтр `minRating` / `maxRating` и сортировка `sort=rating`
  закрывают требование пункта 7.2 ТЗ.
- В карточке вуза считается всегда и раскрывается сильнейшей программой.
- Требует права `ANALYTICS`: представителю вуза закрыты и показатель, и фильтр,
  и сортировка по нему — иначе баллы чужих вузов восстанавливались бы по порядку выдачи.

### Аналитика и рекомендации

Рейтинг программ по трём показателям с раскрытием вклада каждого, skill gap с порогами,
дашборд с происхождением каждого показателя, блок приоритетных действий.

Пять правил генерации рекомендаций: просроченный этап, застой связки, связка без продукта
на этапе оформления, недостающие показатели программы, критичный дефицит навыка при наличии
подходящего продукта. У каждой рекомендации — основание, связанные данные, приоритет,
уверенность и статус. Повторная генерация не плодит дубликаты и не переписывает решение
сотрудника.

**ИИ-помощник (25.09.2026, решение 90).** Черновики по фактам правил: сводка по связке,
письмо вузу по рекомендации, «что сделать сегодня». Российская модель — YandexGPT,

нужен только ключ YandexGPT.

### Кабинет представителя вуза

Роль видит только свой вуз. Аналитика, рейтинги, рекомендации, справочник пользователей и
другие вузы закрыты. Внутренние комментарии к этапам, причины блокировок и заметки по связке
не отдаются. Представитель подтверждает получение материалов, вносит численность обучающихся
и количество групп, подаёт заявки на обучение — `applicationCount` пересчитывается по ним.

### Аутентификация

NextAuth.js с сессиями на JWT, пароли хешами bcrypt. Роль перечитывается из базы при каждом
запросе. Демо-режим переключения ролей без пароля сохранён для защиты проекта и выключается
переменной `DEMO_AUTH_ENABLED`; при выключенном режиме запрос без сессии получает 401.

**Пользователи и пароли (25.09.2026, решение 99).** Администратор заводит пользователей
в «Настройках» — сервер выдаёт временный пароль один раз, в базе только хеш; меняет ФИО,
должность, роль с вузом представителя, блокирует и выдаёт новый пароль. Блокировка
действует сразу, в том числе на выданные сессии. Любая роль меняет свой пароль в личном
кабинете; перебор текущего пароля ограничен тем же счётчиком, что и вход. Пробник
проходит весь путь: заведение → вход по временному паролю → смена → блокировка → разблокировка.

### Групповые операции по IT-продукту

Выпуск новой версии продукта одним действием ставит обязательную задачу во всех связках
с этим продуктом и переоткрывает закрытые этапы передачи материалов. Есть предпросмотр:
менеджер видит список затронутых связок и причину по каждой до применения. Отменённые
этапы операция не трогает — их переоткрывает только администратор поштучно.

### Сборка документов из шаблонов

### Контейнеризация

`Dockerfile` (многоступенчатый, standalone-сборка, образ 331 МБ, запуск не от root,

### Выгрузка в CSV

`GET /api/export` — вузы, программы, связки и дефициты навыков. Файл для Excel:
UTF-8 с BOM, разделитель — точка с запятой, значения вида `=…` обезврежены. Права
совпадают с правами соответствующего раздела: выгрузка не обходной путь к данным.

### Загрузка из CSV

`POST /api/import` — вузы и программы. По умолчанию предпросмотр: запись только при
`mode=apply`. Колонки совпадают с выгрузкой, поэтому цикл «выгрузил → поправил → загрузил»
работает. Записи опознаются по названию — повторная загрузка не плодит двойников.
Строка с ошибкой не отменяет остальные, её номер совпадает с номером строки в Excel.

## Найдено и исправлено при реализации

1. **`.partial()` в Zod не снимает `.default()`.** Пустой `PATCH` молча менял статус записи.
   Затрагивало вузы, программы, связки. Исправлено, закреплено тестами.
2. **`orderBy` с `nulls: 'last'` для non-nullable полей.** Список связок падал с 500.
   Добавлен хелпер `buildOrderBy`, в сквозной сценарий — проверки обоих видов сортировки.
3. **Демо-набор не показывал критичных дефицитов** — главный сигнал системы не был виден.
4. **Спред перезаписывал `id` в `universities.repo.findById`.** Представитель вуза, запросив
   чужой вуз, получил бы свой вместо 404.
5. **Представитель без назначенного вуза видел бы все вузы.** Теперь такой запрос отклоняется.
6. **Комментарий сотрудника затирал обоснование рекомендации.** Заведено отдельное поле.
7. **Правило застоя не срабатывало на начатом этапе** — обобщено на любой незакрытый этап.
8. **Демо-заявки не совпадали с `applicationCount`.** Первая же поданная заявка меняла
   показатель с 420 на 120. Seed приведён в соответствие и сверяет суммы.
9. **`DEFAULT_ROLE_ORDER` не работал:** порядок элементов `IN` в SQL не сохраняется,
   и демо-пользователем оказывался администратор вместо менеджера.
10. **Клиент Prisma создавался при импорте модуля** — это делало нетестируемым всё,
    что транзитивно его тянет. Теперь создаётся лениво.
11. **На чистом клоне падала сборка:** `src/generated` не попадает в репозиторий,
    а `db:deploy` клиент не генерирует. Добавлен `postinstall`. В рабочей копии проблема
    не всплывала — клиент там уже лежал, и поймать её удалось только разворачиванием
    репозитория с нуля.
12. **Сквозной сценарий молча пропускал проверки** на повторном прогоне без пересева:
    искал неподтверждённый материал и закрытый этап, которых после первого прогона
    не оставалось. Теперь сценарий сам готовит себе предусловия.

### Найдено настоящей сборкой образа

24. **`npm install` падал без `DATABASE_URL`:** `postinstall` вызывает `prisma generate`,
    а конфигурация Prisma требовала переменную через `env()`, который бросает исключение.
    Генерации клиента подключение не нужно. Ломало и установку по README, где
    `npm install` идёт до создания `.env`.
25. **`npm run build` падал в продакшене без `AUTH_SECRET`.** Сборка не выпускает токенов,
    и требовать там боевой секрет нельзя: иначе образ не собрать ни в CI, ни где-либо,
    куда секреты попадают только на запуске.
26. **Задача миграции в compose не работала:** в рантайм-образе нет CLI Prisma.
    Собирается из сборочной ступени.
27. **Проверка живости рапортовала «здоров» на базе без таблиц.** Теперь видит
    неприменённые миграции и отдаёт 503.
28. **Контейнерная база конфликтовала с локальной** по порту 5432.

| Два источника рыночных данных за один период дадут навык в списке дефицитов дважды | В MVP источник один (`MARKET_DATA_PROVIDER=mock`), второй появится только вместе с настоящей интеграцией. Тогда и понадобится группировка по навыку — сейчас это код без применения |
| Путь Windows в `MARKET_DATA_CSV_PATH` теряет обратные слэши при чтении `.env` | Настройка относится к источнику `csv`, который в MVP не используется. Обходится прямыми слэшами — работают и в Windows |
| Правка показателей программы через кабинет вуза помечает происхождение всех трёх сразу | Показатели вносятся вместе одной формой, и различать происхождение по отдельности пока незачем. Если понадобится — это три поля вместо одного |
