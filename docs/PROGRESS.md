## Сделано

### Инфраструктура

- Next.js 15.5.25, TypeScript strict, Zod 4 с русской локалью, Vitest 4.
- PostgreSQL 16, Prisma 7 через драйверный адаптер `@prisma/adapter-pg`.
- Миграции через `prisma migrate`, две применённые миграции.
- `docker-compose.yml`, `.env.example` без секретов, `.env` вне репозитория.

### Workflow

14 этапов создаются при создании связки, с чек-листами и нормативными сроками. Машина
состояний по решению 3, условия переходов по решению 4, история с автором и временем,
автоматический пересчёт контрольного этапа 14, просроченные и заблокированные этапы.

### Аналитика и рекомендации

Рейтинг программ по трём показателям с раскрытием вклада каждого, skill gap с порогами,
дашборд с происхождением каждого показателя, блок приоритетных действий.

Пять правил генерации рекомендаций: просроченный этап, застой связки, связка без продукта
на этапе оформления, недостающие показатели программы, критичный дефицит навыка при наличии
подходящего продукта. У каждой рекомендации — основание, связанные данные, приоритет,
уверенность и статус. Повторная генерация не плодит дубликаты и не переписывает решение
сотрудника.

### Кабинет представителя вуза

Роль видит только свой вуз. Аналитика, рейтинги, рекомендации, справочник пользователей и
другие вузы закрыты. Внутренние комментарии к этапам, причины блокировок и заметки по связке
не отдаются. Представитель подтверждает получение материалов, вносит численность обучающихся
и количество групп, подаёт заявки на обучение — `applicationCount` пересчитывается по ним.

### Аутентификация

NextAuth.js с сессиями на JWT, пароли хешами bcrypt. Роль перечитывается из базы при каждом
запросе. Демо-режим переключения ролей без пароля сохранён для защиты проекта и выключается
переменной `DEMO_AUTH_ENABLED`; при выключенном режиме запрос без сессии получает 401.

### Групповые операции по IT-продукту

Выпуск новой версии продукта одним действием ставит обязательную задачу во всех связках
с этим продуктом и переоткрывает закрытые этапы передачи материалов. Есть предпросмотр:
менеджер видит список затронутых связок и причину по каждой до применения. Отменённые
этапы операция не трогает — их переоткрывает только администратор поштучно.

### Сборка документов из шаблонов

Пять шаблонов с автоподстановкой реквизитов вуза, программы, продукта, ответственного
и контактного лица. Недостающий реквизит заменяется видимым прочерком и перечисляется
в ответе — документ не притворяется заполненным. Повторная сборка не плодит дубликаты.

### Спецификация OpenAPI

`docs/openapi.json` и `GET /api/openapi.json` — 49 путей, 62 операции. Собирается из тех же
Zod-схем, которыми API проверяет вход, поэтому не расходится с кодом. Полнота проверяется
тестом: маршрут без описания роняет сборку. Закрывает обещание концепции об описании
интеграционных интерфейсов по спецификации OpenAPI.

### Выгрузка в CSV

`GET /api/export` — вузы, программы, связки и дефициты навыков. Файл для Excel:
UTF-8 с BOM, разделитель — точка с запятой, значения вида `=…` обезврежены. Права
совпадают с правами соответствующего раздела: выгрузка не обходной путь к данным.

### Журнал и лента событий

`GET /api/audit` — технический журнал для администратора. `GET /api/universities/:id/events` —
человекочитаемая лента: этапы, документы, встречи и заявки по вузу.

### Интеграции

`src/integrations`: интерфейс `MarketDataProvider` с реализациями Mock, Csv, ExternalApi,
FutureRtk; клиенты LMS и сайта. Единый HTTP-клиент с таймаутом, повторами, ограничением
частоты и журналированием без тела ответа. Интеграции по умолчанию выключены, их сбой
не ломает систему.

### Демонстрационные данные

6 вузов, 10 программ, 18 навыков, 36 рыночных показателей за два периода, 4 IT-продукта,
7 связок, 98 этапов, 203 пункта чек-листов, 8 документов, 4 встречи, 6 пользователей
(включая представителя вуза).

Набор специально устроен так, чтобы на демонстрации было видно всё: программы без показателей,
просроченные этапы, заблокированный этап, отменённый этап 5, связка без выбранного продукта
на этапе оформления, застоявшаяся связка, два критичных дефицита навыков, документы во всех
статусах. Срабатывают все пять правил рекомендаций.

## Найдено и исправлено при реализации

1. **`.partial()` в Zod не снимает `.default()`.** Пустой `PATCH` молча менял статус записи.
   Затрагивало вузы, программы, связки. Исправлено, закреплено тестами.
2. **`orderBy` с `nulls: 'last'` для non-nullable полей.** Список связок падал с 500.
   Добавлен хелпер `buildOrderBy`, в сквозной сценарий — проверки обоих видов сортировки.
3. **Демо-набор не показывал критичных дефицитов** — главный сигнал системы не был виден.
4. **Спред перезаписывал `id` в `universities.repo.findById`.** Представитель вуза, запросив
   чужой вуз, получил бы свой вместо 404.
5. **Представитель без назначенного вуза видел бы все вузы.** Теперь такой запрос отклоняется.
6. **Комментарий сотрудника затирал обоснование рекомендации.** Заведено отдельное поле.
7. **Правило застоя не срабатывало на начатом этапе** — обобщено на любой незакрытый этап.
8. **Демо-заявки не совпадали с `applicationCount`.** Первая же поданная заявка меняла
   показатель с 420 на 120. Seed приведён в соответствие и сверяет суммы.
9. **`DEFAULT_ROLE_ORDER` не работал:** порядок элементов `IN` в SQL не сохраняется,
   и демо-пользователем оказывался администратор вместо менеджера.
10. **Клиент Prisma создавался при импорте модуля** — это делало нетестируемым всё,
    что транзитивно его тянет. Теперь создаётся лениво.
11. **На чистом клоне падала сборка:** `src/generated` не попадает в репозиторий,
    а `db:deploy` клиент не генерирует. Добавлен `postinstall`. В рабочей копии проблема
    не всплывала — клиент там уже лежал, и поймать её удалось только разворачиванием
    репозитория с нуля.
12. **Сквозной сценарий молча пропускал проверки** на повторном прогоне без пересева:
    искал неподтверждённый материал и закрытый этап, которых после первого прогона
    не оставалось. Теперь сценарий сам готовит себе предусловия.
