# SkillLink --- Design System: Интерфейс и интерактивные элементы

## 1. Назначение документа

Этот документ является обязательным визуальным и интерактивным
стандартом для всего frontend SkillLink.

Главная задача: **не генерировать заново оформление каждого элемента на
каждой странице**. Все описанные компоненты должны быть реализованы как
единая переиспользуемая design system.

Если один и тот же элемент встречается на нескольких страницах, его
внешний вид, размеры, состояния, анимации и поведение должны быть
одинаковыми.

При конфликте с отдельным wireframe приоритет имеют: 1. этот design
system; 2. единая логика продукта; 3. технические ограничения
существующего проекта/API; 4. конкретный wireframe.

------------------------------------------------------------------------

# 2. Общий визуальный язык

## 2.1. Характер интерфейса

SkillLink должен ощущаться как современный premium B2B SaaS:

-   тёмный интерфейс;
-   технологичный;
-   аккуратный;
-   достаточно минималистичный;
-   с неоновыми акцентами;
-   без визуального перегруза;
-   с высокой читаемостью;
-   с мягкими свечениями только там, где они усиливают иерархию.

Визуальное направление можно описать как:

**Dark SaaS + subtle neon + glass-like surfaces + premium gaming-level
interaction polish.**

При этом интерфейс не должен превращаться в игровую панель. Эффект «как
в FC 25--26» использовать только для hover/focus/selection и ощущения
отзывчивости.

------------------------------------------------------------------------

# 3. Базовые поверхности

## 3.1. Основной фон

Использовать очень тёмный холодный фон с лёгким фиолетовым оттенком.

Не использовать чистый #000000 как основной фон.

Фон должен иметь едва заметные радиальные/ambient gradients в отдельных
крупных областях интерфейса.

Градиенты не должны мешать чтению текста.

## 3.2. Карточки

Карточки:

-   тёмнее/светлее основного фона на небольшой величине;
-   тонкая малоконтрастная граница;
-   скругление;
-   мягкая внутренняя глубина;
-   без тяжёлых теней.

Карточка должна ощущаться как отдельная поверхность, но не как плавающий
огромный блок.

## 3.3. Границы

Использовать тонкие borders с низкой контрастностью.

Граница становится немного заметнее при: - hover; - focus; - active; -
selected.

------------------------------------------------------------------------

# 4. Единая система интерактивных элементов

## 4.1. Главный принцип

Все кликабельные элементы должны иметь минимум четыре состояния:

1.  Default
2.  Hover
3.  Active / Pressed
4.  Disabled

Для элементов формы дополнительно: - Focus - Error - Success, если
применимо

Нельзя создавать отдельную стилистику кнопки только потому, что она
находится на другой странице.

------------------------------------------------------------------------

# 5. Кнопки

## 5.1. Общая форма

**Все основные кнопки интерфейса должны быть прямоугольными с сильно
закруглёнными концами.**

Форма --- rounded rectangle / pill-like rectangle.

Не использовать: - круглые кнопки с текстом; - острые прямоугольники; -
разные формы одной и той же кнопки на разных страницах.

Иконка может быть внутри кнопки слева или справа от текста.

## 5.2. Primary Button

Основная CTA-кнопка:

-   яркий неоновый градиент;
-   визуальный акцент от фиолетового/розового к тёплому
    розово-оранжевому;
-   светлый текст;
-   мягкое внешнее свечение;
-   достаточно высокая контрастность.

Применение: - Добавить вуз; - Создать; - Сохранить; - Редактировать
профиль; - Начать; - Выполнить основное действие.

### Hover

При наведении: - кнопка становится немного ярче; - glow немного
усиливается; - возможен очень небольшой подъём; - текст становится
визуально более контрастным.

### Active

При нажатии: - кнопка слегка уменьшается; - glow становится
компактнее; - состояние должно ощущаться мгновенно.

### Disabled

-   убирается яркое свечение;
-   снижается контраст;
-   курсор/интерактивность отключены.

------------------------------------------------------------------------

# 6. Secondary Button

Используется для вторичных действий.

Внешний вид:

-   тёмная поверхность;
-   тонкая фиолетовая/нейтральная граница;
-   rounded rectangle;
-   светлый приглушённый текст.

Hover: - граница становится ярче; - поверхность немного
подсвечивается; - текст становится ярче.

Не конкурирует с Primary Button.

------------------------------------------------------------------------

# 7. Ghost Button

Используется для действий, которые не должны визуально доминировать.

-   прозрачный фон;
-   без тяжёлой границы;
-   приглушённый текст.

Hover: - появляется лёгкая поверхность; - текст становится ярче.

------------------------------------------------------------------------

# 8. Icon Button

Для действий только с иконкой.

Примеры: - уведомления; - закрытие; - дополнительные действия; - back; -
настройки.

Форма: - компактный rounded rectangle; - не делать идеальный круг без
необходимости.

Hover: - мягкая подсветка; - иконка становится ярче.

Active: - более выраженная подсветка.

------------------------------------------------------------------------

# 9. Навигационные элементы Sidebar

Sidebar является отдельной частью design system.

## 9.1. Default

Пункт: - иконка; - текст; - спокойный цвет; - прозрачный фон.

## 9.2. Hover

При наведении:

-   текст становится немного ярче;
-   текст увеличивается очень незначительно;
-   иконка становится ярче;
-   появляется мягкая подсветка поверхности;
-   transition плавный.

Эффект должен напоминать качественную навигационную анимацию в
современных спортивных/игровых интерфейсах, но оставаться
профессиональным.

**Не использовать резкое увеличение масштаба.**

Рекомендуемый визуальный эффект: - font-size: небольшой шаг вверх или
визуальный scale около 1.01--1.02; - opacity → 100%; - icon brightness
↑; - background opacity ↑.

## 9.3. Active

Активный пункт:

-   более яркий текст;
-   заметная тёмно-фиолетовая поверхность;
-   тонкий border;
-   лёгкое внутреннее/внешнее свечение;
-   яркая иконка.

------------------------------------------------------------------------

# 10. Hover-анимации

Анимации должны быть быстрыми и дорогими по ощущению, но не навязчивыми.

Рекомендуемый диапазон: - 120--180 ms для небольших hover; - 180--260 ms
для открытия/закрытия компонентов.

Использовать smooth easing.

Не использовать: - bounce; - сильное вращение; - длинные перелёты; -
постоянное мигание.

------------------------------------------------------------------------

# 11. Глобальный поиск --- новая концепция

## 11.1. Важно

**Постоянную строку поиска в верхней панели удалить.**

Вместо неё должен существовать **глобальный Search Button**,
расположенный в правой нижней части интерфейса.

Это не обычное поле поиска.

Это отдельная floating action button.

------------------------------------------------------------------------

# 12. Floating Search Button

## 12.1. Расположение

По умолчанию:

-   fixed;
-   правый нижний угол;
-   с безопасным отступом от краёв;
-   поверх основного контента;
-   не перекрывает критические CTA.

Кнопка должна оставаться доступной при прокрутке.

## 12.2. Внешний вид

Форма: - rounded rectangle / pill; - неоновый акцент; - иконка поиска; -
короткая подпись, например «Поиск»; - можно добавить keyboard hint.

Не делать огромной.

## 12.3. Hover

При наведении: - немного увеличивается; - glow становится ярче; - текст
становится контрастнее.

------------------------------------------------------------------------

# 13. Окно глобального поиска

При клике на Floating Search Button открывается глобальное поисковое
окно.

Визуальная идея:

**macOS Spotlight**, но адаптированная под SkillLink.

## 13.1. Форма

Окно: - продолговатый горизонтальный овал/rounded capsule; - тёмная
полупрозрачная поверхность; - тонкая светящаяся граница; - мягкий
shadow; - очень лёгкий backdrop blur.

Оно не должно выглядеть как обычный modal.

## 13.2. Позиционирование

Окно должно быть **перетаскиваемым**.

Пользователь может: - взять окно мышью; - перетащить в любую удобную
область экрана; - отпустить; - окно останется в выбранной позиции.

Важно: - drag только за безопасную область окна/header; - нельзя
случайно начать drag при вводе текста; - input должен нормально
работать; - кнопки внутри окна не должны конфликтовать с drag.

## 13.3. Поведение

Открытие: - плавное появление; - небольшое увеличение от 98% к 100%; -
opacity; - лёгкий glow.

Закрытие: - обратная анимация; - без резкого исчезновения.

Закрыть можно: - повторным нажатием Floating Search Button; - Escape; -
кнопкой закрытия, если она предусмотрена.

------------------------------------------------------------------------

# 14. Поисковая строка внутри Spotlight

Внутри окна:

-   большая строка ввода;
-   иконка Search;
-   placeholder;
-   keyboard hint;
-   результаты ниже.

Поиск должен поддерживать глобальные сущности продукта, если
соответствующие API доступны:

-   университеты;
-   образовательные программы;
-   сотрудничества;
-   навыки;
-   документы;
-   другие доступные сущности.

Не придумывать отдельный backend endpoint, если его нет.

------------------------------------------------------------------------

# 15. Search Results

Результаты группируются по типам.

Пример:

**Университеты** - НИУ ВШЭ

**Программы** - Программная инженерия

**Сотрудничества** - НИУ ВШЭ --- Платформа ML

Каждый результат --- интерактивный.

Hover: - surface ↑; - text ↑; - icon ↑; - лёгкий neon accent.

Enter: - открыть выбранный результат.

------------------------------------------------------------------------

# 16. Уведомления

Иконка уведомлений остаётся в верхней правой части header.

Она является активной.

## 16.1. Default

-   icon button;
-   небольшая иконка bell;
-   спокойная подсветка.

Если есть непрочитанные уведомления: - badge с количеством; - аккуратный
glow; - без агрессивного мигания.

## 16.2. Click

При нажатии открывается **notification feed**.

Лента появляется вниз от кнопки.

Это не полноценная страница.

Это floating dropdown / popover.

## 16.3. Повторное нажатие

Повторный клик закрывает ленту.

Также можно закрывать: - Escape; - кликом вне области.

------------------------------------------------------------------------

# 17. Notification Feed

Верх: - «Уведомления»; - количество непрочитанных; - действие «Отметить
всё прочитанным», если поддерживается.

Каждое уведомление:

-   иконка;
-   заголовок;
-   краткое описание;
-   время;
-   статус прочитанности.

## 17.1. Уведомление всегда связано с объектом

Каждое уведомление должно быть активным.

При клике пользователь переходит именно туда, к чему относится
уведомление.

Примеры: - проблема сотрудничества → карточка сотрудничества; - новый
документ → документ; - изменение университета → университет; - задача →
соответствующий workflow; - рекомендация → рекомендация.

Не вести пользователя просто на Dashboard, если существует конкретная
целевая страница.

------------------------------------------------------------------------

# 18. Профиль пользователя в Header

Справа сверху остаются:

-   avatar;
-   имя;
-   фамилия;
-   при необходимости должность/роль.

Вся область является активной.

При клике: → переход на личный кабинет.

Hover: - лёгкое свечение; - фон слегка меняется; - avatar немного
усиливает glow.

------------------------------------------------------------------------

# 19. Avatar

Avatar: - rounded; - аккуратный neon accent; - инициалы или реальное
изображение, если оно доступно.

Не делать постоянную анимацию.

При hover можно добавить лёгкий glow.

------------------------------------------------------------------------

# 20. Badges / Status

Статусы должны быть единообразными.

Использовать: - Active; - In Progress; - Blocked; - Completed; -
Cancelled; - Warning; - Error; - Mock/Demo.

Badge: - rounded pill; - компактный; - цвет зависит от semantic
status; - текст короткий.

Цвет никогда не должен быть единственным способом передачи смысла ---
рядом должен быть текст/иконка.

------------------------------------------------------------------------

# 21. Tabs

Tabs используются на страницах деталей.

Default: - приглушённый текст; - прозрачный фон.

Hover: - текст ярче.

Active: - яркий текст; - нижний neon indicator; - indicator короткий и
аккуратный; - не использовать огромную цветную полосу.

------------------------------------------------------------------------

# 22. Dropdown

Все dropdown должны использовать единый стиль:

-   тёмная surface;
-   rounded corners;
-   border;
-   shadow;
-   backdrop blur при необходимости;
-   item hover с мягким фиолетовым оттенком.

Открытие: - fade + небольшой translate/scale.

------------------------------------------------------------------------

# 23. Modal

Modal используется для действий, требующих внимания.

Структура: - title; - description; - content; - actions.

Основная кнопка справа.

Закрытие: - X; - Escape; - click outside, если действие не критическое.

Для destructive actions click outside может быть отключён.

------------------------------------------------------------------------

# 24. Drawer

Drawer использовать для подробностей, которые пользователь хочет
посмотреть, не покидая текущий экран.

Например: - объяснение рекомендации; - быстрый просмотр документа; -
детали уведомления; - дополнительные данные.

Drawer: - тёмная поверхность; - rounded верхние/внешние края; -
border; - backdrop; - плавное появление.

------------------------------------------------------------------------

# 25. Toast

Toast используется для краткой обратной связи.

Типы: - success; - info; - warning; - error.

Toast: - небольшой; - читаемый; - с иконкой; - короткий текст; -
автоматическое исчезновение только для неопасных сообщений.

Ошибки, требующие действия пользователя, не должны исчезать слишком
быстро.

------------------------------------------------------------------------

# 26. Tooltips

Tooltip только для: - непонятных иконок; - сокращённых названий; -
disabled элементов с объяснением причины.

Не использовать tooltip для очевидного текста.

------------------------------------------------------------------------

# 27. Inputs

Все поля формы имеют единый стиль:

-   dark surface;
-   rounded rectangle;
-   subtle border;
-   placeholder muted;
-   text bright.

Focus: - border становится ярче; - появляется тонкий neon glow.

Error: - semantic error accent; - сообщение под полем.

------------------------------------------------------------------------

# 28. Select / Filter

Фильтры должны выглядеть как компактные rounded buttons/fields.

Например: - Регион; - Статус; - Рейтинг; - Уровень подготовки.

Hover и active аналогичны Secondary Button.

------------------------------------------------------------------------

# 29. Progress / KPI

Прогресс-бары:

-   тонкие;
-   rounded;
-   neon gradient;
-   background приглушённый.

Не использовать слишком толстые полосы.

KPI-значения: - крупные; - хорошо читаемые; - основной показатель
яркий; - secondary text приглушённый.

------------------------------------------------------------------------

# 30. Charts

Графики должны соответствовать общей палитре.

-   тонкие линии;
-   аккуратные точки;
-   мягкое gradient fill;
-   минимум визуального шума;
-   tooltip в едином стиле.

График всегда должен отвечать на понятный бизнес-вопрос.

------------------------------------------------------------------------

# 31. Micro-interactions

Разрешены:

-   hover glow;
-   subtle scale;
-   active press;
-   плавное появление;
-   progress animation;
-   tab indicator;
-   notification badge;
-   мягкий transition цвета.

Запрещены:

-   постоянное свечение;
-   чрезмерные частицы;
-   flashy effects;
-   сильные blur;
-   бесконечные loop-анимации без функциональной причины.

------------------------------------------------------------------------

# 32. Responsive behavior

На меньших экранах:

-   Sidebar может сворачиваться;
-   Floating Search остаётся доступным;
-   Spotlight не должен выходить за границы viewport;
-   popovers автоматически корректируют положение;
-   крупные таблицы переходят в scroll/адаптированный вид.

Dragable Spotlight должен иметь ограничения viewport на маленьких
экранах.

------------------------------------------------------------------------

# 33. Accessibility

Каждый интерактивный элемент обязан иметь:

-   keyboard focus;
-   понятный accessible name;
-   видимый focus state;
-   корректный tab order;
-   aria-label там, где нет текста.

Hover никогда не должен быть единственным способом доступа к функции.

------------------------------------------------------------------------

# 34. Component Architecture

Создать переиспользуемые компоненты:

-   `Button`
-   `IconButton`
-   `SidebarItem`
-   `Header`
-   `FloatingSearchButton`
-   `GlobalSearch`
-   `SearchResults`
-   `NotificationButton`
-   `NotificationFeed`
-   `UserProfileTrigger`
-   `Badge`
-   `Tabs`
-   `Dropdown`
-   `Modal`
-   `Drawer`
-   `Toast`
-   `Tooltip`
-   `Input`
-   `Select`
-   `Progress`
-   `KPI`
-   `Chart`

Страницы должны собираться из этих компонентов.

Нельзя создавать `UniversityButton`, `ProgramButton`,
`RecommendationButton` с независимыми стилями, если визуально это один и
тот же тип кнопки.

------------------------------------------------------------------------

# 35. Ключевое правило для AI-разработчика

Перед созданием нового UI-элемента всегда проверить:

1.  Существует ли уже такой компонент?
2.  Можно ли использовать существующий variant?
3.  Можно ли расширить существующий компонент без копирования стилей?

**Не создавать новый визуальный стиль для уже существующего типа
элемента.**

Цель:

> Один компонент → единый внешний вид → единое поведение → разные
> данные.
