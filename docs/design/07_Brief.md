--------------------------------------------------
1. ГЛАВНАЯ ПРОБЛЕМА ТЕКУЩЕЙ ВЕРСИИ
--------------------------------------------------
Сейчас интерфейс слишком однообразный:
- показатель = тёмная карточка;
- таблица = тёмная карточка;
- этап = тёмная карточка;
- почти везде одинаковые скругления;
- почти везде одинаковые фиолетовые границы;
- почти везде одинаковый glow;
- почти везде розово-фиолетовый gradient;
- у каждой плитки декоративная иконка;
- слишком много одинаковых контейнеров;
- недостаточно визуальной иерархии;
- мало элементов, характерных именно для SkillLink.
Так делать НЕЛЬЗЯ.
Нужно создать визуальную систему, в которой разные типы информации выглядят по-разному.
Данные должны выглядеть как данные.
Рабочие процессы — как workflow.
Связи — как связи.
Университеты — как сущности.
Рекомендации — как рекомендации.
Этапы — как последовательность.
Floating UI — как floating UI.
Не помещай всё подряд в одинаковые карточки.
--------------------------------------------------
2. НЕ ДЕЛАЙ "КРАСИВО РАДИ КРАСИВО"
--------------------------------------------------
Мне нужны красивые, очень плавные и приятные анимации.

Но анимации НЕ должны быть декоративным шумом.
Каждая заметная анимация должна объяснять:
- изменение состояния;
- переход;
- связь между объектами;
- появление данных;
- движение пользователя по интерфейсу;
- изменение этапа;
- открытие сущности;
- отношение между вузом, программой и продуктом.
Главный принцип:
CONTINUITY OVER SPECTACLE.
Но это НЕ означает, что сайт должен быть скучным или статичным.
Наоборот — интерфейс должен ощущаться живым, дорогим и очень плавным.
Пользователь должен чувствовать качество интерфейса, а не замечать отдельные "эффекты".
--------------------------------------------------
3. ВАЖНО: НЕ ПРЕВРАЩАЙ САЙТ В ИГРУ
--------------------------------------------------
Не использовать:
- постоянный glow;
- частицы;
- случайные светящиеся объекты;
- огромные 3D-эффекты;
- бесконечные анимации;
- чрезмерный parallax;
- сильный blur;
- карточки, которые постоянно подпрыгивают;
- огромный scale;
- flashy effects;
- animated gradients на всём сайте;
- декоративные сферические 3D-объекты;
- случайные WebGL-эффекты.
Мне нужен профессиональный интерфейс, а не gaming UI.
--------------------------------------------------
4. ПРИ ЭТОМ АНИМАЦИИ ДОЛЖНЫ БЫТЬ ЗАМЕТНЫМИ
--------------------------------------------------
Не сделай ошибку и не убери анимации настолько, что сайт станет статичным.
Мне нужны:
- плавные появления;
- плавные переходы;
- последовательные reveal-анимации;
- мягкие движения;
- transitions между состояниями;
- morphing;
- FLIP-переходы;
- SVG line drawing;
- count-up;
- небольшая глубина;
- аккуратный 3D tilt;
- плавное изменение масштаба там, где оно оправдано;
- плавное появление данных;
- stagger для связанных элементов.
Но всё должно быть дозировано.
--------------------------------------------------
5. ГЛАВНАЯ СТРАНИЦА
--------------------------------------------------
Полностью перестрой Home согласно MD.
НЕ ДЕЛАЙ четыре одинаковые KPI-карточки.
Вместо этого создай:
SKILLINK LIVE RAIL.
Это должна быть единая визуальная композиция, которая показывает:
- активные связи;
- университеты в работе;
- этапы, закрытые вовремя;
- среднее время до найма.
Например:
Active connections
Universities in work
Stages closed on time
Average time to hire
Но эти показатели не должны выглядеть как четыре одинаковых карточки.
Они должны ощущаться как единая система данных.
Добавь:
- count-up;
- появление точек;
- появление линий;
- аккуратную прорисовку графических элементов;
- последовательный stagger;
- один небольшой meaningful active pulse.
После завершения entrance-анимации всё должно успокоиться.
Никаких бесконечных анимаций.
--------------------------------------------------
6. SKILLINK LINK MAP
--------------------------------------------------
Создай один из главных уникальных элементов SkillLink:
COMPANY → UNIVERSITY → PROGRAM → PRODUCT
Используй SVG.
Между сущностями должны быть реальные линии.
При появлении страницы:

1. появляются сущности;
2. затем линии плавно прорисовываются;
3. активная связь получает небольшой импульс;
4. при hover связанные элементы подсвечиваются;
5. несвязанные элементы слегка приглушаются.
Это должно стать одной из визуальных особенностей продукта.
Не использовать случайные линии ради декора.
Каждая линия должна что-то означать.
--------------------------------------------------
7. 14 ЭТАПОВ
--------------------------------------------------
Создай:
14-STAGE DEPTH RAIL.
Не делай 14 одинаковых карточек.
Используй CSS perspective.
Логика:
- завершённые этапы визуально уходят назад;
- текущий этап находится на переднем плане;
- будущие этапы находятся дальше;
- текущий этап визуально наиболее важен;
- переход между этапами должен быть плавным.
Например:
08 / 14
должно восприниматься как часть workflow, а не просто цифра на карточке.
При переходе:
completed → назад
current → foreground
future → дальше
Сделай это аккуратно и профессионально.
Three.js для этого НЕ нужен.
Используй CSS perspective + transforms.
--------------------------------------------------
8. TABLE → DETAIL
--------------------------------------------------
Очень важно.
Когда пользователь нажимает на университет в таблице:
НЕ делай обычное:
table disappears → new page appears.

Сделай визуальную continuity.
Логика:
1. выбранная строка подсвечивается;
2. остальные строки слегка приглушаются;
3. название выбранного университета визуально сохраняется;
4. оно плавно переезжает в заголовок страницы;
5. остальные элементы страницы появляются вокруг него;
6. пользователь ощущает, что он продолжил движение внутри той же системы.
Используй FLIP/View Transitions/clone overlay там, где это уместно.
Обычного fade недостаточно.
--------------------------------------------------
9. LOGIN → DASHBOARD
--------------------------------------------------
Авторизация должна ощущаться как часть той же системы.
НЕ делай:
login page → abrupt dashboard.
Сделай:
Login → Workspace transition.
На login:
- появляется canvas;
- появляется SkillLink wordmark;
- прорисовывается связь;
- появляется auth panel;
- появляются поля.
После успешного входа:
- auth panel плавно трансформируется;
- связь продолжается;
- появляется sidebar;
- появляется header;
- появляется Live Rail;
- затем появляются остальные элементы.
Переход должен ощущаться как одна сцена.
Примерная продолжительность:
700–950ms.
Но пользователь должен получить возможность начать взаимодействовать примерно через 450–550ms.
Не блокируй интерфейс долгой анимацией.
--------------------------------------------------
10. HOVER И MICROINTERACTIONS
--------------------------------------------------
Сделай hover очень аккуратным.
Карточки и сущности могут:
- слегка приподниматься;
- немного смещаться;
- менять surface;
- менять яркость текста;
- показывать связанную информацию.
Для некоторых важных сущностей разрешён CSS 3D tilt.
Максимум:
rotate ≈ 2.5deg
translateZ ≈ 8px
Это должно быть ощущение настоящей глубины, а не trading card effect.
НЕ применяй tilt ко всему сайту.
Только к действительно подходящим сущностям.
--------------------------------------------------
11. SIDEBAR

НЕ:
- огромный glow;
- градиентный прямоугольник вокруг active item;

Active navigation:
- вертикальный marker;
- изменение typography;
- небольшое изменение яркости;
- возможно translateX ≈ 3px.
Hover должен быть плавным.

33. КРИТЕРИИ ГОТОВОГО РЕЗУЛЬТАТА
--------------------------------------------------
После реализации я должен увидеть:
- отсутствие ощущения AI-generated SaaS;
- отсутствие одинаковых карточек повсюду;
- чёткую visual hierarchy;
- реальную связь между IT-компанией, вузом, программой и продуктом;
- 14-stage workflow;
- живой Home;
- профессиональные transitions;
- очень плавные animations;
- аккуратный 3D depth;
- meaningful hover;
- красивый login → dashboard transition;
- плавный table → detail transition;
- Spotlight Search;
- notifications;
- понятную типографику;
- умеренное использование accent colors;
- минимум декоративного glow.
Главное:
Сайт должен быть одновременно:
ПРОФЕССИОНАЛЬНЫМ
ЖИВЫМ
ПЛАВНЫМ
УЗНАВАЕМЫМ
ПРАКТИЧНЫМ
НЕПОХОЖИМ НА AI TEMPLATE
--------------------------------------------------
34. ФИНАЛЬНАЯ УСТАНОВКА
--------------------------------------------------
Не делай "красивый SaaS dashboard".
Сделай визуальный язык конкретного продукта SkillLink.
Не добавляй эффекты поверх generic SaaS.
Построй характер через:
структуру,
данные,
связи,
этапы,
типографику,
композицию,
continuity.

И только после этого усиливай всё motion-анимациями.
Мне нужны действительно приятные, плавные и дорогие на ощущение анимации, но они должны быть осмысленными.
Когда пользователь взаимодействует с интерфейсом, он должен понимать, что произошло не только по изменению цвета, но и по движению самого интерфейса.
Особенно внимательно проработай:
LOGIN → DASHBOARD
TABLE → DETAIL
UNIVERSITY → PROGRAM
PROGRAM → PRODUCT
STAGE → NEXT STAGE
SPOTLIGHT → RESULTS
NOTIFICATION → PAGE
Не ограничивайся простым fade-in.
Мне нужна визуальная continuity между состояниями.
После завершения работы самостоятельно проверь весь интерфейс по acceptance criteria из MD-файла и исправь найденные проблемы.
Не считай задачу выполненной только потому, что CSS выглядит аккуратно.
Задача выполнена только тогда, когда SkillLink перестаёт выглядеть как шаблонный AI SaaS и начинает ощущаться как самостоятельный, продуманный продукт с собственной визуальной логикой.
