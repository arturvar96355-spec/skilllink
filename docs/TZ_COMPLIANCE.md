# Соответствие ТЗ РТК: где проверить каждый пункт

Построчная сверка с официальным текстом ТЗ заказчика (`Система контроля и обработки
статистических данных по обучению студентов ВУЗов и школ по ИТ направлениям`, 2026,
9 страниц) — по разделам и нумерации самого документа. Файл ТЗ не хранится в
репозитории (в `.git/info/exclude`), но прочитан целиком. Сверено с кодом и журналом
решений до решения 228 включительно (28.09.2026).

Для каждого пункта: что он требует (коротко, своими словами) → статус → где на стенде
https://skilllink.site → какой маршрут API → решение в [журнале](TECHNICAL_DECISIONS.md).
Учётные записи — в [README](../README.md), раздел «Попробовать».

Статусы — у каждой строки ровно один:

- **готово** — есть и экран, и API (или пункт не про API — тогда просто сделано);
- **API** — есть API, экрана нет; проверяется в Swagger UI на стенде
  ([`/api-docs`](https://skilllink.site/api-docs), после входа) или запросом;
- **частично** — сделана часть; чего нет — одной строкой в той же строке таблицы;
- **вне репозитория** — пункт выполняется не кодом (например, файл презентации на платформе конкурса).

Разделы 1–3 ТЗ (список сокращений, актуальность задачи, описание задачи) и раздел 9
(критерии оценки) не содержат отдельных проверяемых требований к решению — они не
включены в таблицы, но прочитаны и учтены при формулировках ниже.

## Что сделано частично — сводка

Те же строки, что помечены «частично» в таблицах выше, — одним списком:

- **Маппинг колонок при импорте** — формат файла фиксированный, настраиваемого маппинга нет.
- **Второй workflow** — этапы переименовываются и получают свои сроки, но процесс один, из 14 этапов.
- **152-ФЗ, ФСТЭК, 149-ФЗ** — меры реализованы, формального заключения о соответствии нет.
- **Кэш действий пользователя** — точечные кэши есть, единого слоя нет: пункт ТЗ неоднозначен.
- **Каталог заказчика** — на стенде синтетические данные, реальный каталог не получен.

## Учётные записи для экспертов

`expert-manager@`, `expert-admin@`, `expert-rep@skilllink.demo` — только чтение и
выгрузки: сервер отклоняет любое изменение, экран не показывает кнопок изменения
(решение 147). Вход — кнопками «Вход для экспертов хакатона» на `/login` без пароля
(решение 176) или обычной формой: у учётных записей экспертов свой пароль, он передаётся
в файле на платформе конкурса и не открывает учётные записи сотрудников (решение 228).
