# SkillLink — каталог элементов и связей модели

Файл-справочник для ручной сборки модели в Archi, если импорт `SkillLink-architecture.archimate`
всё же не пройдёт. Сгруппировано по слоям ArchiMate. В скобках — идентификатор из XML.

## Бизнес-слой

### Активные структурные элементы (Business Actor)
- Менеджер по вузам (`id-ba-manager`)
- Руководитель (`id-ba-lead`) — переименован из «Руководитель менеджеров»
- Администратор платформы (`id-ba-admin`)
- Представитель вуза (`id-ba-rep`)

### Процессы (Business Process)
- Привлечение (`id-bp-attract`)
- Оформление (`id-bp-formalize`)
- Внедрение (`id-bp-implement`)
- Эксплуатация (`id-bp-operate`)

### Бизнес-объекты (Business Object)
- Связка вуз-программа-продукт (`id-bo-cooperation`)
- Этап workflow (`id-bo-stage`)
- Документ (`id-bo-document`)
- Рекомендация (`id-bo-recommendation`)
- Рейтинг программы (`id-bo-rating`)

### Бизнес-сервисы (Business Service)
- Ведение сотрудничества с вузами (`id-bs-cooperation`)
- Формирование отчётности (`id-bs-reporting`)
- Аналитика рынка труда и навыков (`id-bs-analytics`)

## Слой приложения

### Компоненты (Application Component)
- Веб-интерфейс (`id-ac-webui`)
- API-слой (`id-ac-api`)
- Сервис Workflow (`id-ac-workflow`)
- Сервис Рекомендаций (`id-ac-recommend`)
- Сервис Аналитики (`id-ac-analytics`)
- Сервис Документов (`id-ac-documents`)
- Сервис Пользователей и Прав (`id-ac-users`)
- Сервис Журнала действий (`id-ac-audit`)
- ИИ-помощник (`id-ac-ai`)
- Сервис Импорта/Экспорта (`id-ac-io`)
- **[новое]** Telegram-бот уведомлений (`id-ac-telegram`)
- **[новое]** YandexGPT (внешний сервис ИИ) (`id-ac-yandexgpt`)

### Прикладные сервисы (Application Service)
- Управление связками (`id-as-cooperation`)
- Формирование рекомендаций (`id-as-recommend`)
- Расчёт рейтинга программ (`id-as-rating`)
- Аутентификация и авторизация (`id-as-auth`)
- Генерация отчётов (`id-as-reports`)

### Интерфейсы (Application Interface)
- REST API (`id-ai-restapi`)
- **[новое]** POST /api/import/external (`id-ai-import`)

### Объекты данных (Data Object) — имена на русском
- Вуз (`id-do-university`, было University)
- Программа (`id-do-program`, было Program)
- IT-продукт (`id-do-product`, было ITProduct)
- Связка (`id-do-cooperation`, было Cooperation)
- Этап (`id-do-stage`, было WorkflowStage)
- Документ (`id-do-document`, было Document)
- Рекомендация (`id-do-recommendation`, было Recommendation)
- Пользователь (`id-do-user`, было User)
- Журнал действий (`id-do-auditlog`, было AuditLog)
- **[новое]** Файл (`id-do-file`)

## Технологический слой

### Узлы (Node)
- Сервер приложения (Docker) (`id-nd-appserver`)
- Сервер базы данных (Docker) (`id-nd-dbserver`)
- Обратный прокси (Caddy) (`id-nd-proxy`)

### Системное ПО (System Software)
- Node.js Runtime (`id-ss-node`)
- PostgreSQL Server (`id-ss-postgres`)

### Технологические сервисы (Technology Service)
- Хранение данных (`id-ts-storage`)
- HTTPS-терминация и маршрутизация (`id-ts-https`)
- **[новое]** Файловое хранилище (сервер) (`id-ts-files`)

### Артефакты (Artifact)
- Docker-образ приложения (`id-art-image`)
- **[новое]** Файл отчёта (CSV/XLSX/JSON) (`id-art-report`)

### Локация (Location)
- Yandex Cloud (Россия) (`id-loc-cloud`)

## Представления (views)
1. **«Слои: общая схема»** — бизнес-акторы, процессы, бизнес-объекты, бизнес- и прикладные сервисы, ключевые компоненты (веб-интерфейс, API), узлы, локация.
2. **«Приложение: компоненты и данные»** — все компоненты приложения, интерфейсы, прикладные сервисы, объекты данных, артефакт отчёта.
3. **«Развёртывание»** — локация, узлы, системное ПО, технологические сервисы, артефакт Docker-образа, размещённые на нём компоненты.
