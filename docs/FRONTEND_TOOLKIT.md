# FRONTEND_TOOLKIT — навыки, библиотеки, референсы и правила для фронта SkillLink

> Для Claude Code в проекте SkillLink. Прочитай целиком перед задачами по интерфейсу.
> Цель: довести фронт до уровня сильного enterprise-дашборда **без генерации картинок и без платных API** —
> только навыки с GitHub, существующий стек, референсы и правила.

## 0. Приоритет источников (не нарушать)

1. `CLAUDE.md` проекта и раздел «Принятые решения» — главнее всего.
2. `docs/FRONTEND.md` — как устроен интерфейс и жёсткие правила.
3. `docs/design/07_Human_Crafted_Override.md` — главный документ дизайна, дальше 01–06.
4. Этот файл — инструменты и практики. При конфликте с пунктами 1–3 прав проект.

**Ограничения проекта, которые меняют выбор инструментов:**
- Tailwind и UI-библиотек нет: оформление через CSS-переменные в `src/app/globals.css` и CSS Modules.
  Библиотеки на Tailwind и shadcn (Kokonut UI, Bklit UI, 21st.dev, shadcn Blocks) — **только как референсы**:
  смотрим идею и поведение, переносим в `src/ui/` на наших токенах. Не устанавливаем.
- Новые npm-зависимости — только с обоснованием в отчёте (зачем, чем не справляемся без неё, вес).
- Уже есть и используем: **Motion** (анимации), **three.js** (3D, пример — сцена входа в фоновом потоке),
  свои графики в `src/ui/data` (Funnel, Donut, BarsFlat, RussiaMap, Metric, Table, States).
- Никаких зарубежных облачных сервисов в рантайме.


## 0.1. Сроки, темы, режимы, автотесты (дополнение 27.09, решение владельца)

**Сроки.** Крупные изменения интерфейса — до вечера 28.09. 29.09 — только правки. После 23:59 29.09 стенд не трогаем (дисквалификация). Никаких установок, которые меняют сборку, в последние сутки.

**Обе темы.** Каждый экран проверяется в светлой и тёмной теме. Солнце и месяц в переключателе темы не трогать. Нынешние 3D-кольца сохранены тегом `design/rings-3d-2026-09-26` — вернуть: `git checkout design/rings-3d-2026-09-26 -- src/ui/data/Pie3D.tsx src/ui/data/Pie3D.module.css src/ui/data/Bars3D.tsx src/ui/data/Bars3D.module.css src/ui/data/Ring.tsx src/ui/data/Ring.module.css`.

**Режимы и роли.** Каждый экран проверяется:
- в витрине (презентационный режим) и в рабочем;
- под экспертом (только чтение, кнопок изменения нет);

**Наши автотесты, которые ломаются от правок фронта:**

- внутренние ссылки — только `next/link` (тест внутренних ссылок);
- числа в документах совпадают с кодом (тест счётчиков).

**Из раздела 6 берём в работу первыми:**
- п. 3 — шапка перекрывает приветствие;
- п. 5 — одна база подсчёта чисел на всех экранах.

**Спорные пункты (обсудить с владельцем 27.09):**
- бегущая строка — оставлена, сделано перетаскивание (#192);

## 4. Правила (из docs/FRONTEND.md, UX-аудита и практики)

**Жёсткие (из проекта):**
1. Никаких новых цветов, радиусов и размеров шрифта в компонентах — только переменные `globals.css`.
2. Сначала существующий компонент или его вариант; новый вид кнопки/карточки не создаётся.
3. `null` — «Нет данных», не ноль (`MetricValue`, `KpiCard`).
4. Демо-данные помечены `MockBadge`.
5. Текст ошибки приходит с сервера и выводится как есть.
6. У каждого экрана 4 состояния: скелетон, ошибка, пусто, данные.
7. Клавиатура и видимый фокус, `aria-label` у элементов без текста.
8. Ничего не выходит за ширину экрана; декоративные слои `fixed; inset:0; pointer-events:none`; `overflow-x: clip` у html/body не трогать.
9. Типы — только из `@/shared/contracts`, никакого `@/generated/prisma` на фронте; данные — через API.

**Против «ИИ-шного» вида:**
- Карточки только для объектов, которые выбирают, сравнивают или открывают. Лишние контейнеры убрать.
- Реестры по умолчанию **списком/таблицей**; «бирки»/карусель — переключаемый режим, не дефолт.
- Декор на рабочих экранах (бегущие строки, заставки, 3D ради 3D) — только если несёт смысл.
- 3D-графики: только если читаются лучше плоских; подписи значений всегда видны, есть плоский фолбэк.

**UX для CRM (минимум лидеров рынка):**
- «Мой день» на главной: мои объекты, просрочено у меня, шаги на сегодня.
- Шапка карточки: ответственный, представитель, следующий шаг и срок, последняя активность.
- Изменить / удалить / архивировать у каждой сущности; создание из интерфейса.
- Пользователи и роли с экраном прав, журнал действий.
- Одно действие — одно место ввода (статус связанной сущности меняется правилом на бэке).
- Просрочка — только у текущих начатых этапов.
- **Числа согласованы между экранами** (счётчики, «N из M», проценты) — одна база подсчёта.

**Процесс на большом проекте:**
- Одна задача = один экран или один компонент. Не рефакторить вне задачи.
- Перед правкой: прочитать `docs/FRONTEND.md`, нужный раздел `docs/design/`, найти существующий компонент.
- До и после правки — скриншоты Playwright на 390 / 768 / 1440; приложить к отчёту.
- Перед сдачей: `/impeccable audit` → `polish`, консоль браузера без ошибок, `npm run typecheck` и тесты зелёные.
- Анимации: `prefers-reduced-motion`, 3D в фоновом потоке, пауза вне экрана.

## 6. Что видно по текущим скриншотам (первые задачи)

1. **Бегущая строка** под приветствием — декор на рабочем экране, читается плохо. Заменить блоком
   «Требует внимания» или убрать.
2. **«Вузы» открываются «бирками» 1/17** — сравнить вузы нельзя. Дефолт — таблица/список, бирки — режим.
3. **Шапка перекрывает приветствие** при скролле (липкая навигация режет «Доброй ночи»). Проверить отступ/фон шапки.
4. **3D-кольца «Здоровье портфеля»** — эффектно, но значения читаются хуже плоских; добавить подписи
   процентов на секторах и плоский режим, проверить `prefers-reduced-motion`.
5. **Плотность и согласованность чисел**: «65 связей», «77 в воронке», «24 из 65 на маршруте» — одна база
   подсчёта и явные подписи, откуда число.
6. Проверить каждый экран на 390 px — сейчас скриншоты только десктопные.
